## painted-animation skill：新增「0.35 编剧」步（故事先于画面）

**动因**：用户提出 MV 容易偏离歌词，应在画分镜前先像编剧一样写故事，再由故事长出场景、由场景出分镜。
诊断：原 skill 只有**镜头级因果**（相邻两镜「这一镜导致下一镜」），保证接得上但不保证「有人在等一个结果」，
于是每镜都兑现、都好看，全片仍像精美图文朗读。

**确定的设计决策**
- 顺序：量拍（段落骨架）→ **编剧** → 歌词兑现表 → 场景表 → 分镜。编剧不能排在量拍前，
  否则故事高潮落不到副歌上，只能剪歌迁就剧本。
- 交付物五样：logline（必须有「但」）、一人一欲（只在转折改一次）、**实体化阻力**（能画出来，不写「犹豫」）、
  节拍表（3–5 拍绑死段落+歌词行+秒，无归属的歌词行不许进兑现表）、首尾押韵。
- 双向测试：抽掉歌词故事还成立？抽掉画面歌还成立？两个都成立才是 MV。
- 三方服从关系：选材时歌词 > 故事；排布节拍时故事 > 单句歌词；定切点时节奏 > 故事。
  （因此不进 C1–C6 裁决表，另立一张「按阶段换边」的表）
- 场景仍是结果不是起点——中间必须保留兑现表这一环，否则回到 checklist 里「先定地点再塞事件」的老坑。
- 按片长缩放防止过度设计：<60s 只写 logline+三拍，1–3min 五样齐全，>3min 分节拍表分幕。
- 不进用户确认点，与设计表同级（有效确认点仍只有粗样片 + 渲染授权）。

  §0.5 顺序行加入故事；规则汇总新增第 1 条「先有故事，再有镜头」（原 1–7 顺延为 2–8）；交叉引用「第一节」→「第二节」。

## 新增「场景要能被认出来」判据（用户提出：场景应是现实的投射、要有沉浸感与熟悉感）

**用户诉求**：MV 的故事场景要像现实的投射，不能太抽象；场景元素要让人有沉浸感、熟悉感。

**判断**：合理，且补的是一个真空——四份文档里「沉浸」「熟悉」「写实」零命中，「抽象」只在 checklist 一条失败记录里出现过。
原 §四 只回答「场景里该有多少东西、多久换一次」（物件预算 6–8 件、换景频率），
不回答「这些东西该是什么性质」。所以规则能保证画面不空，保证不了画面是真的。

**但改了一个词**：不是「现实的投射 / 写实」，是「可辨认的具体」。
理由：媒介是纯平面色块 + 沸腾墨线，画不出写实也不该追求；观众要的不是「像」，是「认」。

**核心判据（新增）**：
1. **四档梯度**：抽象符号 → 类型清单 → 可辨认的具体（熟悉感在此出现）→ 唯一的那一家（能装故事）
2. **通用清单测试**：列出物件，划掉「这种地方都该有的」，剩 0–1 件 = 类型背景板；剩 ≥2 件且有例外 = 熟悉感成立
3. **第 2 档最危险**（新增洞见）：类型清单看起来「什么都有」，盘点挑不出缺什么，会骗过审片；比第 1 档更隐蔽
4. **沉浸感来自被使用，不来自被填满**：物件必须跟角色发生物理接触（扶栏杆、玻璃起雾写字、鞋踩积水）；
   明确写「6–8 件是上限不是 KPI」，防止这条规则被落地成「每景多塞道具」——那是 checklist 里记过的旧翻车方向
5. **抽象是呼吸不是敌人**：只在极特写（C6 豁免）、情绪爆发、时间跳跃/转场三处脱开现实
6. **深浅按剧情分配**：全片第 3 档铺，只有 2–3 个关键景做到第 4 档（与兑现配额同理，由剧情给不由镜头数给）

**落点（三处 + 自检）**：
- `design-first.md` §四 新增小节，插在「换景不等于换地点」与「每段的预算」之间（先定性质再定数量）；
  节标题改为「场景：先能被认出来，再按段给预算」
- `design-first.md` §八 自检新增「可辨认」一条
- `SKILL.md` §0.5 补编排层判据（第一句 + 指向第四节）
- `checklist.md` 交付前必查，紧跟「故事成立且有归属」之后

**校验**：五份文档逐字重复长句 = 0；链接全部有效；表格列数一致。
体量：SKILL 435→442、design-first 391→428、checklist 108→115。

## 角色一致性 + 配件连贯性：四步防线落地（引擎改造，不只是文档）

**用户的课题**：1) 角色形象全流程一致（前后缺胳膊少腿、圆头变方头）；2) 配件在角色身上的位置合理且从头保持到结束。

**判断**：这是架构题不是文档题。铁证：cast.js 写着「画角色走包装」，而模板自带的 demo.js 就在直接调 clawd()——
文档规则被模板自己违反。所以「写规则」已被证明无效，解法是「让违规不可能」。

**发现的三个泄漏点（具体到代码）**：
1. 形象规格不存在任何地方——VIEWS 表里 side 视图本来就只画一条手臂（正确遮挡），但没有「这个角色=4腿2臂」的声明
2. 视图可以硬切——turn() 存在但没人拦；front→side 直接切，观众读成断臂
3. 配件靠每镜手传，缺失是默认行为——extras(hat/draw/armL/armR) 由调用方传；{...o} 展开链最后一个，null 悄悄盖掉

**核心原则**：一致性不能靠「每次记得」，只能靠「没有能力忘记」。

**落地的四步**：
1. **cast.js 规格化**：CAST 加 rig{legs,arms,head} + props{常驻配件}；包装函数从表**自动生成**（加角色只改一行，
   防线自动覆盖）；guard() 拦五类违规：rig/legs/arms/head/noLegs 出现在场景 opts、直接传配件键（绕过 props）、
   props 未知键（typo 不静默）、props=null（要拿掉必须写 'off'——「忘了」和「故意」必须长得不一样）。
   注意：guard 不拦 col/dk/lt——emotions 带 base 时返回值里合法地含颜色，拦了会误杀标准写法。
2. **clawd.js + core.js + render.mjs 契约表**：clawd() 每帧记录角色 key/view/屏幕bbox（__CAST_LOG，draw() 清空，

   空位画暗格标「—」好数「从哪一镜起不见了」；render.mjs --cast 默认每镜取中点。
3. **scripts/check_cast.mjs 静态检查**（秒级、不碰浏览器）：直接调 clawd( / spread CAST / emotions 无 base /
   props 未声明键 → 错误；noLegs / 多个 view 字面量 → 提醒人工核对 turn()。退出码接入流程。
4. **文档**：ANIMATION_GUIDE 加「规格与一致性」节 + 钩子节区分常驻/一次性配件（示例代码也改走包装）；

## 重写 design-first §三「歌词兑现」：直译划界 + 记账单位由行改成拍

**用户诉求**：怀疑 §三 有问题，想删掉，担心「直译」出问题。

**结论：不删，改。** 诊断出三个缺陷（前两个是真硬伤，不是文风）：
1. **直译没有划界**：它定义的是「名词动词不许换」（关于内容的判据），写法却全是「逐行三查 / 逐行标哪一镜」，
   被读成「每一行配一个镜头」＝逐行配图——正是上一轮 story 层（§一）刚治掉的病，这一节从背后放回来了。
2. **记账单位与 §一 冲突（硬伤）**：§一 节拍表按**拍**（3–5 拍，一拍绑 2–4 行，例表 4 拍盖 7 行），
   §三 按**行**（逐行三查 + 全片最多 2 行不兑现）。一拍盖 3 行 = 9 条 reads，而每镜上限 3 条 →
   这一拍至少 3 个镜头且零余量，压到 2 个必然违约。**按行记账时 §一 推荐的节拍表本身就违规。**
3. **抽象名词没有出口**：时差/遗憾/沧桑 过不了三查第 1 条，唯一解法藏在 checklist 的失败记录里
   （「抽象名词先变成能碰到的东西」），没在判据层。这正是用户担心的「直译出问题」的确切位置。

**改动**：
- `design-first.md` §三：改标题为「一拍一译，行可以合并」；加划界句；新增「记账单位是拍，不是行」（含为何不能按行算）；
  新增「抽象名词：先变成能碰到的东西」三步表（实物 → 动词 → 变化）+ 判据「画完能不能一句话说回那个词」；

## 角色归属 + 音画同步（用户两条实测问题）

**问题 1：歌词里该 B 做的事画成了 A 做，B 的物品挂到 A 身上。**
根因：cast.js 的三道防线（规格/props 默认继承/guard）管的是"角色长什么样"，"动作和道具挂在谁身上"
没有任何机制管——分镜事件字段"谁做了什么"里的"谁"不是结构化数据，代码里两人同框全凭复制粘贴。
修复三层：
1. `SKILL.md` §1 事件字段改写：**必须以 CAST 角色名开头**，一个动作一个主语；**道具跟人走**——
   "她摘帽递给他"是两次转移（前半帽在 A 头上、后半帽在 B 手里），写成两段。
2. **契约表加配件标签**：cast.js 包装登记 `__CAST_PROPS_BY_KEY[name]`，clawd 记进 `__CAST_LOG`，
   renderCastSheet 格底黑条显示 `q ·hat` 之类——**帽子在谁头上，看表**。摘掉那镜标签自动消失（已实测）。
3. `check_cast.mjs` 加多角色同框提醒（⚠ 不报错）：逐镜核对主语与配件归属。
   **踩坑两个**：① eachCall(name) 内部自己拼 `name+'('`，我传 `n+'('` 去找 `man((` 永远落空——
   插桩才抓到；② studio.html 只加载 demo.js，测试文件必须伪装（**第二次踩同一个坑**）。

**问题 2：先出画面、歌才出（音画不同步）。**
诊断（都是实测，不是猜）：AAC 编码往返互相关 = **0ms**，编码器嫌疑排除；`shots()` 的 t0 从 0 开始
= 片段内时间，引擎链路正确；`frameOf` 不减偏移、`--clip` 不带 range 时 a=0，正确。
**根因**：karaoke.js 注释规定的"LY 时间 = LRC 减去片段起点"是**纯手工减法**，PROJECT 里没有
clipStart 字段，减错了没有任何地方能发现——三个数（LY、合成 -ss、镜头表）各算各的。
修复（单一真相源）：
1. `PROJECT.clipStart`（默认 0，向后兼容）。设了它，**LY 直接抄 LRC 绝对时间**，不再手减。
2. karaoke `overlayHook` 内部 `q = t + CLIP0`（CLIP0 只在 core.js 定义一次）。
3. render.mjs 的 encode / animatic / clip 三处合成全部读 `src/config.js` 的 clipStart（正则，
   不依赖浏览器）；clip 的 `-ss` 从 `a` 改 `a + clipStart()`。
验证：clipStart=100 + LY 绝对时间 [100,104]，渲 t=1.0 出字幕、t=10.5 不出（还原图确认）；
还原后 --clip 冒烟 duration 正确。**给了二分诊断法**：字幕与唱词对得上 = 音频链路没错，
是镜头进入时刻提前；字幕也不对 = clipStart 错。写进 SKILL 时间轴小节。

**遗留**：镜头进入 vs 歌词开口的"提前量上限"没有判据（先出画面有多少是设计、多少是错，只有人能判）；
互相关测量脚本（/tmp/avx.py 验证过 ±120ms 精确）没有固化进 scripts/，需要时再固化。
