# 故事契约：把歌词解读冻成两份文件

## 为什么非要有这个文件

§0.35 的复述如果只活在对话里，会在三个时刻蒸发：上下文被压缩、隔天接着干、换个子代理接手。
蒸发之后每个镜头都「看起来对」，但没人能回答最简单的问题——**这一句是谁对谁说的。**

一支真实翻过车的片子（56 秒、23 镜）留下两个硬伤，都不是画得不好，是没人落字：

- 歌词唱「**你**对我说的情话」，画面里是**他**张嘴说话。整首词的叙事者是他（「爱炙热的**你**」＝她烧红，
  「却忘了爱**自己**」＝他），所以情话必须出自她的嘴。这一错，人物关系整个反了。
- 罐子在第 20 镜放在她门口、走了；第 23 镜罐子又在他手上还剩一颗。梗概写的是「只留下最后一颗」——
  **罐子留下了，球带走了**。画面把「放下」拍成了「拿走」。

两个都是**写下来就不会犯**的错。写下来还不够，得让脚本能查——所以契约有两份：人读的 `STORY.md`，
机读的 `story.json`。

## 什么时候写

**§0.35 用户点头之后、§0.4 兑现表之前。半小时写完，不求文采。**
写早了没意义（故事还没定），写晚了兑现表已经按错的理解铺开了。

## STORY.md：六块，一块不许省

```markdown
# <歌名> · 故事契约
状态：FROZEN 2026-11-16   ← 改动必须重新报用户

## 1. Logline
一句话：谁 ＋ 想要什么 ＋ 但 ＋ 结果。

## 2. 叙事者契约（全片唯一真理源）
| 歌里的「我」 | 歌里的「你」 | 谁唱给谁 | 依据 |
|---|---|---|---|
| 他（陶土橙） | 她（青蓝·围巾） | 他唱给她 | 「爱炙热的你」「忘了爱自己」 |

## 3. 逐行直译（行数＝歌词行数，一行不许合并）
| # | 秒 | 原词 | 直译（名词动词不许换） | 谁对谁 | 这一行必须看见 |
|---|---|---|---|---|---|
| 9 | 28.60–31.38 | 你对我说的情话 | 你说给我听的情话 | 她 → 他 | 她的嘴在动，话变成可见的东西 |

## 4. 情绪弧线（四拍，各一句）
遇见 → 相守 → 情话 → 时差。写"每一拍结束时观众该松一口气还是该揪一下"。

## 5. 母题链（一个符号，变形 N 次）
符号：一颗光球。s13 掉进掌心 → s14 从她嘴里出来 → s15 上天炸开 → s17 碎成屑 → s23 映出他自己。

## 6. 道具账本（每件道具一条链）
| 道具 | 出场 | 转手 | 离场 | 终态 |
|---|---|---|---|---|
| 罐子 | s13 他手里 | s14 举着 | s20 放在她门口台阶 | 留在门口（不在他手上） |
| 纸船 | s01 脚边 | s03 她递给他 | s04 起不再出现 | 收起来了 |
```

**第 2 块和第 6 块是重点。** 第 2 块定死人称，第 6 块定死道具。这两块没写，后面全是猜。

## story.json：给脚本查的子集

只写 `lyric_audit.mjs` 要用的字段，别把 STORY.md 全文抄一遍。

```json
{
  "narrator": { "me": "him", "you": "her", "singingTo": "her" },
  "lines": [
    { "i": 9, "speaker": "her", "addressee": "him",
      "act": "说情话，话变成光球", "key": { "shot": "s14", "what": "她开口" } }
  ],
  "shots": [
    { "id": "s14", "speaker": "her", "cast": ["him", "her"], "props": ["jar"] }
  ],
  "props": [
    { "name": "jar", "terminal": ["left", "gone"],
      "states": [["s13", "hand"], ["s14", "hand"], ["s20", "left"], ["s23", "gone"]] }
  ]
}
```

- `speaker` 只填**这一镜真的在说话的人**；纯画面镜留空（`null`），别填叙事者。
- `cast` 填这镜在画面里的人；`props` 填这镜在画面里的道具。
- `props[].states` 按**镜头顺序**排，`terminal` 是「一去不回」的状态集合。

## 审计规则：脚本查七条

`node scripts/lyric_audit.mjs` 用 `src/karaoke.js` 的 `LY` 和 `src/scenes/*.js` 的 `shots()` 当真值，
`story.json` 只提供意图，两边对账。

| # | 查什么 | 判 | 出问题怎么修 |
|---|---|---|---|
| C1 | 每行词有没有镜覆盖 | 空档 ❌ | 补镜或挪切点 |
| C2 | **这行的说话人 = 覆盖镜的说话人** | 冲突 ❌ | **改画面，不改歌词** |
| C3 | 行的主体在不在这一镜的 cast 里 | 缺席 ❌ | 补人进画，或换镜 |
| C4 | 行的关键动作镜是否比这行早 1.2s 以上 | 偏拍 ⚠ | 挪动作，**不挪切点**（切点归节拍） |
| C5 | 道具过了终态又回来 | 复活 ❌ | 补一个「取回」镜，或改终态 |
| C6 | 一行被 4 镜以上覆盖 | 偏碎 ⚠ | 合并镜，别逐行配图 |
| C7 | 契约里这行没写说话人 | 缺项 ⚠ | 回去补 STORY.md 第 3 块 |

**C2 与 C5 是那两次翻车的原样复现**：说话人反了、道具复活了。

## 出问题时的优先级

1. **改画面，不改歌词。** 歌词是甲方，画面是乙方。
2. **偏一拍优先挪动作。** 切点是节拍算出来的，为迁就一句词去改切点，整段的呼吸就乱了。
3. **道具断了优先补镜。** 用旁白、字幕、倒影去解释"其实他后来又拿回来了"，是拿观众的注意力还债。

## 和兑现表的分工

- **兑现表（§0.4）**：按**拍**记账，管"这一拍有没有把名词和动词兑现"——创作工具，给自己看。
- **故事契约 + 审计**：按**行**记账，管"这一句谁对谁做、和画面对不对得上"——验收工具，给闸门用。

两份都写不重复：兑现表回答"够不够"，审计回答"对不对"。
