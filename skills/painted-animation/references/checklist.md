# 交付前必查，以及别再试的方案

## 零、正式渲染之前：三段审片必须走完

按代价从低到高，**每一段都要真的做，不能跳**。跳过的代价是整片返工（一次 30 分钟起）。

- [ ] **4a 静帧**：`--sheet` 看构图、`--strip` 看动、`--crop` 看脸。每镜至少一帧。
- [ ] **4b 全片总结图**：`--sheet=1,3,…,55 --cols=4 --w=480 --out=out/overview.jpg`（28 帧 / 约 15 秒）。逐条自问：
  - [ ] 数得出几处不同的地方？少于场景表的数量 → 相机没退开，或场景没真的换
  - [ ] 相邻两段的颜色一样吗？像一张单色纸 → 回去重画色彩表
  - [ ] 每行的构图是同一个形状吗？都是"左暗+中人+右雨" → 换构图骨架
  - [ ] 人物占画面高度多少？超过 1/2 的镜头占多数 → 相机要退
  - [ ] 有没有哪一格是纯转场中间态（整屏被斜向色条/纯色块覆盖）→ wipe 太满，收窄或换转场
  - [ ] 每格左上角的时间码都清楚吗（看不清说明单格太小，加大 `--w` 或减少帧数）
- [ ] **4c 动效预览**：`node render.mjs --animatic --step=4`，**必须带原曲听完**。
  - [ ] 动作卡在拍子上吗（尤其转身、落地、抬手）
  - [ ] 转场接缝有没有硬切/闪跳
  - [ ] 字幕与唱词咬合吗，有没有串行或提前消失
  - [ ] 有没有哪一段"什么都没发生"（超出设计意图的静止）

这三段全过之后再申请正式渲染，并在申请时报告帧数和耗时。

## 一、交付前必查（不查完不许发）

勾完这六条再说话。每一条都对应一次真实的翻车。

- [ ] **`ffprobe` 硬指标对得上**：`duration` 与 PROJECT 一致（56.24 就该是 56.24，不是 41.7）、
      帧数 = `round(duration × fps)`、有音轨、分辨率正确。
      **不要只看那句 `wrote out/video.mp4`**——序列中间缺一帧，ffmpeg 会静默截断，照样打这行。
- [ ] **全片抽帧拼 contact sheet 通看过**：数得出几处地方？相邻两段颜色一样吗？每行构图是同一个形状吗？
- [ ] **每个接缝都看过**：首尾各 0.5 秒，有没有硬切、有没有两镜同时动闪底色。
- [ ] **字幕抽查**：没有串行、没有提前一句或拖后一句、没有压在人物脸上。
- [ ] **有没有文字/3D/纯黑纯白**：除了歌词和极少数拟声字，画面里不该出现字。
- [ ] **已知取舍写清楚了**：哪几处自己不满意、为什么、下一版怎么改。

## 二、交付说明写这几行

用户要的是"能不能用"，不是过程：

```
成片：<路径>  1920×1080 / 24fps / <时长>s / h264+aac
视觉：<画风一句话>，六处场景，共 <N> 镜
字幕：<N> 句，逐字填充，字体 <字体名>（回退 <系统字体>）
音频：原曲直出；源文件本身有 <x>% 采样过载（非本片引入）
耗时：全片 <x> 分钟；后续单镜改动约 <x> 分钟
已知取舍：<如实写 1–3 条>
```

## 三、已经试过、不要再试的方案

| 方案 | 实测结果 | 结论 |
|---|---|---|
| 背景只用 `fill` 画（没有 `wash`） | 平面版里它会降级成半透明色块，看着像没铺满 | 改：实体一律 `wash`，`fill` 只当第二层明暗 |
| 转场 wipe 用亮黄（伞的颜色），5 条笔触铺满全屏 | 24fps 下只有 0.15 秒，但划过时像一道闪光；用四五次就成了噪音 | 改：换成本场戏的过渡色（深褐→深蓝），或减到 3 条笔触 |
| 从 WEBGL 迁到 canvas 2D 时留着 `translate(-W/2,-H/2)` | 整张画面偏移半幅，人物只出现在一个圆圈里 | 改：2D 画布原点已在左上角，这行删掉 |
| `studio.html` 里漏挂 `karaoke.js` | 整片字幕消失，控制台一声不响 | 改：挂在 `timeline.js` **之后**（它要读 SHOTS / DUR） |
| 场景文件顶层写 `const DUR` | 和 core.js 的全局常量撞名，整页白屏报 `Identifier has already been declared` | 改：换个名字（`TOTAL`） |
| `glow` 画在主体之前 | 绘制立即生效，后画的主体直接盖住光 | 改：光画在它要照亮的东西**之后**、前面的东西**之前** |
| `boilSeed` 只在外层播一次，靠 `random()` 让雨有变化 | 一个会动的元素让后面所有东西每帧重新抖，画面"沙沙"响 | 改：每个独立元素前单独 `boilSeed(key)` |
| 两个角色同框时不写 `boilKey` | 默认按调用顺序编号，角色进出画时编号错位，画风串 | 改：显式 `boilKey: 'A'` / `'B'` |
| 自定义颜色的角色直接用 `emotions(t, keys)` 再 spread | 表情一换角色就变回默认赭色（粉色变橙），过渡瞬间还闪 | 改：`cast.js` 里包一层 `lanMood = (t,keys) => emotions(t, keys, { base: CAST.lan })`，表情只走包装 |
| 挂件（围巾/背包/挂牌）手写 y 坐标 | `-7.5u` 看着像脖子，画出来在头顶上——身体顶边就是 `-8u` | 改：位置读 `CLAWD_ANCHORS`；渲一帧 `--anchors` 红线标注对一眼 |
| 10 路并发想压满 CPU | 6 个以上 page 同时初始化互相拖死，22 秒渲出 0 帧 | 改：`--workers=6` |
| 帧序列中间缺一帧（删除范围与重渲范围没对齐） | ffmpeg 到缺口就停，成片静默变短（41.7 秒而非 56.2） | 改：帧号 = `round(t × fps)`，出片前 `ffprobe` 核帧数 |
| 还照着水彩版的写法传 `border` / `tex` / `bleed` | 三个参数已从引擎删除，传了不报错也不生效，调半天没有变化 | 改：要体积就叠两层 `washOp`，要边缘就自己 `inkLine` |
| 换了场景就以为解决了"单调" | 相机还怼在中景，景物全被挤到边缘，观众认不出换了地方 | 改：场景镜头 `zoom` 压到 0.74–0.92 |
| 六个场景都画成"左暗体 + 中人 + 右空" | 换的是墙纸不是空间，观众仍然觉得是同一个地方 | 改：每个场景换一种构图骨架（见 design-first.md） |
| 改完源码直接跑 `--animatic`，看到画面没变以为是“改坏了” | 帧缓存只看文件存在不看源码——源码全换了也静默复用旧帧，出一版和上次字节相同的“新样片”，拿旧片当新框架审 | 改：渲染器已加 `.srcsig` 指纹，源码变了自动清帧；交付前 `md5` 新旧输出必须不同 |
| 在成片上看问题 | 一支 56 秒的片子重渲了四次，每次 28 分钟 | 改：所有检查前移到 `--sheet` / `--strip` / `--crop` |
| **先定地点，再往每个地点里塞事件** | 七处场景、七个色相、七种骨架，用户仍然逐条点出"拨开阴霾没看到、收集快乐没看到、时差没体现"——逐行对下来 14 行歌词只有 2 行真落地 | 改：先做**歌词兑现表**（动词 / 承受动作的实物 / 做完画面哪里变了），地点是结果不是起点 |
| 用氛围代替动作兑现歌词 | "拨开阴霾"画成擦窗户、"收集快乐"画成一面照片墙——同类气氛，但那件事没发生 | 改：抽象名词先变成能碰到的东西（灰幕 / 光点 / 分屏），再把动词给它 |
| 欢快的歌做成灰暗夜戏 | 用户只说了一句"这个歌听起来是欢快的，但 mv 风格偏灰暗色调" | 改：明度由歌定不由题材定，主色明度 65–85%，压暗必须能引用一句歌词 |
| 七个场景全是中景平视 | 换够了地点仍然"场景切换单调、缺乏创意"——观众看到的是同一张明信片换底图 | 改：尺度 / 空间逻辑 / 视点高度 / 载体，每段至少动两种 |
| 场景里只放三四件东西 | "场景里的元素过于单调"，观众一眼看完就没得看 | 改：每景列 6–8 件可辨物件，2 件前景、1 件会动 |
| 把画风磨到完美再往后铺 | 框架方向一旦错，磨得越细废得越多；用户要的是先看粗样片 | 改：16 镜先全搭一遍（每镜 5–10 分钟），框架过了再回头磨细节 |
- **不要手算帧号删帧再 `--range` 重渲**。删的范围和重渲的范围差一帧，序列就断，ffmpeg 静默截断成片
  （上一版就出过：以为 56 秒，实际 41 秒）。改用 `--dry-run` 看它打算渲哪些，或 `--only=s09`。
- **不要先渲全片再看效果**。这条被反复证明：先渲 1350 帧再发现"场景太单调""人裁头"，就是整片重来。
  审片三段（静帧 → 总览 → animatic）加起来不到 2 分钟。
